# PRD 与设计：后续新任务工作流

读取项目本次明确的需求、原材料、既有成果与定制，先说明新增/变化的必要行为及未决事实。用原需求编号对应本次 PRD、状态转换、原型和独立核对，不因公共能力目录缺少条目而删除需求。只展开实际需要的行为；不套固定行业状态、页面数、宽度或评分门槛。

沿项目交付的实际工具更新原型。若项目采用 model/config/renderer，修改其真实输入并调用声明 renderer；保留用户定制，避免只改生成 HTML 在后续渲染时丢失修复。任务指定输入保留、失败重试、返回行为、布局或可访问性时，将它们交给独立观察。HTML 字段和状态名存在不能证明交互正确。原型演示服务不代表真实云 API 或账号服务验收。

交付 task 声明成果、使用说明及真实执行记录；只带项目需要的工具与声明宿主，不依赖搭建聊天的隐藏脚本。生产者不读取独立预期或填写审阅 PASS。当前任务的 scope、原预算、原恢复和既有修复职责继续适用。

生产 attempt 完整交回后，外层宿主按 task.host_tools 调用实际浏览器。当前可选接口为 `mcp__cua_repl`：按当时工具说明选择浏览器，读取其 API 文档，再对声明 URL 操作、读回并截图。文件服务如有需要，按当前已声明范围启动并保留停止句柄；只清理本次创建的服务/标签，不停止别人的进程。不假定 file://、视口设置或浏览器控制能力一定可用；记录实际工具限制，不能用静态文件检查替代。操作顺序、尺寸与判定义务来自本项目需求。

宿主对照原需求记录真实状态变化、输入是否保留、图像与执行日志，并说明独立判断理由。将受审成果和实际观察通过 snapshot.py 固定到新目录，独立检查消费保护副本。新需求、新成果及升级后的受影响行为要有新观察；未受影响旧证据仅在明确条件相同时复用并说明范围。工具没运行的项目保留 NOT_RUN／UNKNOWN，不由工具名称或快照创建推定完成。
