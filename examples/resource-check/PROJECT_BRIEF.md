# Resource check 合成接入案例

这是公开合成项目，用来验证既有资源接入流程，不调用模型或外部服务，也不代表运行批准。
产品读取 fixtures/rows.json 的 values 数组，统计元素数量、整数总和及非整数数量；布尔值算非整数。
给定 [3, 4, "invalid", 5]，产物 outputs/summary.json 必须为 {"rows": 4, "total": 12, "invalid": 1}。
非对象输入或非数组 values 必须以退出码 2 和 INVALID_INPUT 诊断拒绝，不生成成功产物。
验收在声明的产品副本运行同一工具，只在 .cache 和 build 生成缓存与结果；正式产品不生成这些文件。
独立检查器从受保护 expected.json 读取预期，使用 unittest 验证产品、专属临时文件、SQLite WAL、提交/回滚、迁移和重开。
默认验收网络为 NONE；只有显式选择本机服务变体时，检查器才建立一个 127.0.0.1 临时端口 HTTP 实例，核对本次 command 身份并关闭实例和线程。
判定失败与运行异常必须区分；完整报告交给既有宿主归档。成功资源按原机制清理，失败证据保留，恢复不得重放已完成命令。
本例不覆盖真实账户、外部 API、测试凭据、生产数据库、递归目录输入、长期后台服务或恶意产品的对抗隔离。
