# 例示：音频选段交付与宿主审听

这是公开开发设计片段，未调用任何媒体工具、模型或服务。示例中的选择用于说明职责和交接，不要求新项目采用相同工具或任务拆分，也不构成运行授权。

## 示例原需求

用户从自己提供的一段录音中，按指定起止时间制作短音频。保留原文件，导出约定格式，并检查边界附近是否出现截断或明显突变。用户之后可能调整选段和淡入淡出参数，要求通过同一套交付规则处理新任务。超出录音范围的时间不能默默截短；没有完成审听时如实说明。

需要自动检查的是输入可解码、时间范围、实际导出格式和对应片段；“截断或突变”的听感还需要已声明的宿主审听。二者不能互相代替。精确时间口径和可接受误差来自实际产品合同，不能直接从本例补成固定数值。

## 方案与合法替代

可以复用已声明的本地媒体工具完成探测、选段和编码，目标 Harness 保存任务参数、调用入口、输出位置及待审听状态，外层宿主用实际可用的播放工具审听。这些工具可以是项目已有封装，也可以是已绑定的通用命令；无需先制作一个媒体能力包。

另一种合法方案是让宿主现有音频编辑工具负责选段和导出，项目只提供参数与结果交接说明，独立工具读取导出文件核对客观字段。只要宿主接口真实可用、范围已声明且结果可观察，两种方案均可成立。只有用户需要实时交互编辑时才考虑相应界面，不为一次选段默认搭建媒体平台。

| 责任 | 实际交接 |
| --- | --- |
| 外层 Codex／宿主 | 确认任务口径和实际工具；展示搭建文档与运行范围；需要时实际播放并保存审听观察 |
| 项目实施或已有工具 | 读取原录音与参数，执行声明的处理，输出音频及调用记录；原录音只读 |
| 目标 Harness | 提供后续输入与参数入口，关联输出和当前状态，明确未完成审听或导出未知等未决事项 |
| 独立检查方 | 从导出字节及公开合同检查客观结果；核对审听观察是否对应实际导出版本 |
| Foundry | 沿原有计划、授权、检查、预算和恢复接口推进，不拥有听感判断能力 |

先推演输入路径、时间单位、解释器或程序入口、临时文件、输出目录及播放器能够读取的位置。声明工具已安装和路径可解析不代表实际编码依赖齐全；运行获准后，按所选环境进行必要的小型调用验证，保留工具错误。无需模型处理的音频工作可以由本地命令完成，不能因有模型就增加转写或内容改写。

## 宿主工具怎样接续

如果 CODEX 子任务不能使用宿主播放器，设计不能声称它会自行审听。可将第一次独立接受明确限定为自动处理及客观检查；外层随后实际审听固定导出文件，再由后续 LOCAL 检查读取受保护的观察。最终结论分别说明自动字段与审听结果，不把前段接受扩大为全部音频质量通过。

`ONE_ATTEMPT` 只在完整一次实施及检查结束后交回，不能在生成和验证之间暂停等待播放器。后续检查复用已声明导出物，不能为了取证重放已完成的选段。若真实审听发现违约，回原生产者的适用修复入口处理，再对新导出版本做受影响的检查；固定复制器不能修复音频。

## 交付和独立预期

交付包含实际需要的规则、参数说明、调用入口、工具依赖及结果记录方式。新会话能够定位原录音、原参数和导出版本，不借用旧聊天中的临时命令；目标不携带宿主私有判定材料或开发机环境。

独立预期先由原合同确定。公开开发录音可以用于接通工具；保留验证使用未参与调参的输入，原始材料与私有判定分别保存。进程成功和媒体元数据只覆盖客观部分，播放工具打开文件也不等于审听结论。若只完成自动检查，就将听感保持未验证；若输出或过程状态未知，先核对已有记录和实际文件，不自动从头重做。

后续参数修订通过同一交付入口接受新任务。修复 Harness 规则或入口应另记版本及覆盖，不把修后使用说成原版已证明。示例未执行这些步骤，也不以本例的描述替代真实工具接入和新会话使用证据。
