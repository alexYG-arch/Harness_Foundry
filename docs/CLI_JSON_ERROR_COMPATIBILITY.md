# 通用 CLI 参数错误 JSON 与元数据修正

本说明记录 v1.0.0 之后的源码修复，不是新 Release，也不替换已发布的 v1.0.0 固定包。产品版本保持1.0.0，协议保持2.9；原R3、既有验收分母及预算规则不变。

## 行为与兼容

通用 CLI 的未知命令、缺少必填参数、未知选项和互斥选项，现在向 stdout 返回一个 JSON 错误对象，退出码为2。沿用 `REQUEST_VALIDATION_ERROR`，诊断原因为 `error.details.reason_code=CLI_ARGUMENT_ERROR`，并给出 `writes_performed=false`、`execution_started=false`。这一格式不依赖是否显式传入 `--json`。

解析失败发生在读取请求、打开控制库和派发业务之前。正常调用、帮助文本和帮助退出码0保持不变，原有非法参数仍被拒绝。详细接口见 [通用 CLI 说明](GENERIC_BUILD_CLI.md)。历史源码诊断命令不在本次调整范围内；通用运行包不提供 `verify-spec` 或 `validate-core`，初始检查使用 `version --json` 和 `--help`。

架构说明采用当前 Plan 1.2，保留与1.1的兼容关系。Manifest 的 `verification_resources_update.status` 改为 `IMPLEMENTED_RELEASED_SOURCE`，对应已经交付的资源能力，不代表本次源码补丁已发布或真实服务验收完成；`real_user_service_acceptance=NOT_RUN` 保留。

`core_completion` 的历史值不改，新增 `core_completion_scope` 说明它仅属于历史基线回归，不代替当前通用路由、发行包或真实项目验收。数据库权限、历史判定逻辑、调度、授权及恢复实现均未调整，不扩展G1/G2或增加通用限制。
