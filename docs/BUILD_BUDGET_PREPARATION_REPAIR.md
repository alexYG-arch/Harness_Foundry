# 搭建预算与限时准备补修

基线为 v1.2.1／d2981a8，协议2.9。以下记录源码补修及提交前工程验证；本次纳入 main
源码提交，不表示已发布或已升级其他部署。远端 CI 与本机验证分别核对，不合并测试计数。
旧固定包、接受结果、控制记录和累计消耗保持原样，不操作其他项目的活动库。

## 已实现

- `preview-build`、准备返回和 `read-build` 增加只读 `budget_planning`：按完整 Plan
  分列首次生产尝试、模型调用、独立检查命令和声明的环境预检。初始预算不足或没有返修
  余量时提示，不改额、不拒绝有限执行。已执行或接续后的完整计划参考不是剩余工作量，
  不要求重跑接受结果、只复验或完整捕获。原预算投影、计费和批准逻辑不变。
- 模型实际调用材料增加 `command_time_budget`，明确整次模型调用共用的限时、构造调用时
  的有效秒数和到期时间。原硬超时及授权到期仍生效；没有自动延长、取消限额或逐阶段新预算。
- 准备时提前发现“把已声明产物文件或 CODEX 工作目录指令文件作为目录写根”的错误，
  包含在文件下创建目录的冲突。它们原本就无法满足目录与文件的运行约定；本次只前移
  诊断，保留合法父目录、目录别名及含点目录，不按扩展名推断所有路径类型。
  后续小修使准备与接收器共用指令候选解析：非空 override 覆盖 fallback，空或缺失
  override 继续回退；未被覆盖的缺失目标仍参与目录冲突诊断，链接按实际目标比较。
  被有效 override 遮蔽的同名目录保留，所选非普通文件仍沿原读取检查拒绝。
- 源码 Skill、运行包 Skill、设计指南及 CLI 同步估算方式和增额例外：不机械套用2/3次
  或900秒；依据任务、所选工具及适用历史耗时准备余量。显式增额复用已有
  `rebind_from`／`budget_extension`；只延时也沿原接续批准，保持原尝试上限。

主入口为 `build_state.py`、`build_preview.py`、`build_entrypoint.py`、`build_display.py`
和 `build_runtime.py`。没有新增控制器、批准类型、强制预检、真实模型调用或后台服务。
原尝试消费保留，准备失败与实际模型消耗分别说明，不能将次数换算成未观察的 Token 或金额。
原先已批准的配置不会被这些提示修改；完整报告恢复不重新构造或重放旧命令。
