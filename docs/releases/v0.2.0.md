# Harness Foundry v0.2.0

用 Codex 搭建项目专属 Harness，支持从完整 PRD 开始的新项目，以及保留既有行为的增量开发。
产品版本 0.2.0，协议版本 2.9，MIT 许可。

## 下载与开始使用

下载本 Release 的 **Harness-Foundry-0.2.0-generic-3c52c30.zip**，解压到独立目录，
在 Codex 中打开。请保留隐藏的 `.agents/` 目录，不要把自动生成的 Source code ZIP/TAR 当成运行包。

在解压目录检查入口：

```bash
python3 tools/hffactory.py version --json
python3 tools/hffactory.py --help
```

然后向 Codex 提供 PRD 或项目说明，请它使用本目录的 `harness-foundry-build` Skill，
先展示搭建文档；你确认后，再展示并批准模型、工具、目录和预算，随后自动推进建设。

详细步骤见[使用指南](https://github.com/alexYG-arch/Harness_Foundry/blob/main/docs/USER_GUIDE.md)。

## 环境要求

- Python 3.11+；通用运行包仅使用 Python 标准库，无第三方 Python 运行依赖。
- 可用、已登录的 Codex 和模型服务；执行器需要兼容的 CLI 与有效原生沙箱。
- 当前实际运行环境：macOS、Python 3.13.3、Codex 0.155.0-alpha.9.2、GPT-6 Astra。
  其他客户端版本需先核对接口；Linux/Windows 暂不承诺同等原生运行支持。
- 项目自身的编译器、测试库等需另行准备并声明。
- macOS 下不使用共享 `/tmp` 或 `/private/tmp` 存放运行包、输入、控制库或目标。
- 模型调用需要网络并使用你的账号；本地任务命令默认不联网，不捆绑模型、凭据或插件。

## 本版功能

- 通用搭建流程：需求澄清、可审阅文档、明确运行范围、实施、独立检查、修复与继续。
- Codex 自主选择推理与实现方式，本地程序承担确定性步骤。
- 显式任务依赖与读写范围，保存执行进度，不逐内部任务重复请求批准。
- 对业务缺陷、需求/检查约定缺口、环境错误和未知结果分别处理。
- 支持根据完整记录继续工作；不会在无法判断是否已执行时盲目重跑。
- 不内置固定行业流水线，不要求用户手工操作冻结令牌或 Hash 链。

## 场景与案例

**Task CLI 新项目：** 从任务管理 PRD 搭建 Coding Harness，再使用它开发新增、列出、
完成、删除任务与 JSON 持久化功能。

**CSV 已有项目增量：** 为现有汇总工具新增必填列检查与 strict 模式，同时保留原命令、
公开 API、测试和用户笔记，不修改输入 CSV。

运行包内 `examples/` 提供完整需求和起始代码，不是已经完成的应用。
案例操作见[使用指南中的案例说明](https://github.com/alexYG-arch/Harness_Foundry/blob/main/docs/USER_GUIDE.md#案例说明)。

## 兼容性与支持

新建仅使用通用 Build；旧 Start Package/Candidate/epoch/Driver 新建入口已退役。
升级使用独立目录，保留旧程序与数据，不自动迁移旧控制库或继承旧运行批准。

普通问题通过 [Issues](https://github.com/alexYG-arch/Harness_Foundry/issues) 提交去敏复现；
漏洞使用[私密报告](https://github.com/alexYG-arch/Harness_Foundry/security/advisories/new)。
不保证任意故障自动恢复；需要浏览器、插件或任务内联网的流程应先核对当前执行器能力。
