## 主要变化

- 所有新建统一进入通用 Build：澄清需求 → 展示搭建文档 → 人工确认 → 展示并批准有界运行。
  之后自动实施、独立校验、有限修复、依赖推进和恢复，不逐 Workpack 请求批准。
- Codex 负责推理和实现，Python 可以承担确定性阶段；不内置视频或固定行业流水线。
- 公共来源全文保留，Case 绑定公开验收合同；控制器提交独立检查结果，不将模型自报当验收。
- 正常业务断言、合同缺口、基础设施错误与未知副作用分流；明确的上游产物缺陷可交回
  原生产者，在原写域/预算内失效并重验依赖，不能让消费者越权修复。
- 测试工作目录、解释器与子进程显式绑定，兼容开发内部 scratch 和只读验收外部 scratch；
  保留 unittest failure/error 分类，避免日志污染结构化结果。
- 完整耐久观测可恢复且不重复实施；撤销/到期、预算和隔离边界仍生效。
- 仅保留必要归档/指定验收对象身份检查，不新增消息、日志或回执 Hash 链。

## 支持环境与依赖

通用编译/只读 CLI 需要 Python 3.11+ 标准库，无第三方 Python 运行依赖。
真实端到端仅在 macOS、Python 3.13.3、Codex 0.155.0-alpha.9.2、GPT-6 Astra 验证；
不据此宣称 Linux/Windows 原生执行或真正第三方用户试用通过。
Python、Codex、模型服务由使用者合法提供，适用各自许可/条款，不捆绑账号、模型或认证文件。
开发测试 extras 不是运行包依赖，历史规范 sibling 也不是运行依赖。

共享 `/tmp`（含其解析别名）不满足当前 macOS 原生只读隔离要求；不得存放运行包、输入、
验证器、控制库或目标。使用普通独立项目目录，核对实际原生读写限制；不可无沙箱降级。
模型服务会接收所声明输入与代码，非“完全离线”。使用者须实际批准服务和输入范围。

## 接入与升级

```bash
python3 tools/hffactory.py version --json
python3 tools/hffactory.py --help
```

向 Codex 提供完整需求/PRD/项目说明，先审阅其展示的搭建文档，再批准明确运行范围。
无需手写内部 JSON 或复制冻结 Hash。运行前声明实际模型、程序、指令读取、目录、预算和期限。

这是生产路线变更：旧 Start Package/Candidate/epoch/Driver 新建入口退役，不能回退启动。
旧关闭的 authoring 数据库仅用 read-history；通用 REVISION_V1 用 read-build，格式不自动迁移。
升级用独立目录并保留旧程序/状态；新安装不继承旧批准，回退不撤销已发生副作用。
本版 0.x 不承诺任意未来版本兼容；已有用户合同变更需要明确处理，不静默扩大范围。
