# Harness Foundry v1.2.0

稳定产品版本 **1.2.0**，协议保持 **2.9**。本版从v1.1.0加入通用能力连接、全部／按需选择和交付机制，以及8个内置参考能力新版本。相对于rc.3，运行实现与能力文件不变，只更新产品身份、测试常量、打包文档选择及交付说明。旧标签、Release和附件保留，不包含具体第三方提供方实现。

## 新增能力

- 连接目录或ZIP，绑定来源与版本，发现并加载所选资料和Skill。连接不等于安装、运行或授权。
- ALL全部接入、ON_DEMAND选择性接入；功能入口、共享文件、工具环境及最终交付形态分别绑定，保留旧入口。
- 通用原生工具适配接口、非标准包声明转换和有边界的改写准备；实际提供方行为需要各自声明和验证。
- 交付清单、受保护检查、接收端重新绑定及报告恢复；连续升级沿原G/C/N保留定制、冲突和历史。
- qt-cmake@3、python-environment@2、data-summary@2、doc-export@2、host-review@2、local-dashboard@5、text-count@2、reference-notes@2。旧能力版本保持不变。

## 修复项

- 按最终交付形态核对依赖，保留合法搭建期依赖及AS_IS/BRIDGED组合。
- 功能选择不再混入同一连接的旧Skill列表，其他连接和旧入口不受影响。
- 决定绑定相关来源并在交付前核对；无关变化与同字节迁移保留决定复用，不新增审批层。
- Qt/Python依赖观察兼容同一Mach-O文件的多架构标题；未知输出仍拒错。
- 目标看板按实际交付功能核对共享依赖；回环监听避免无关反向DNS查询，保留报告、恢复及清理语义。

以上实现已包含在rc.3。本次正式版没有另行修改调度、授权、预算或业务算法。

## 获取与升级

从[正式版附件](https://github.com/alexYG-arch/Harness_Foundry/releases/tag/v1.2.0)下载：

- `Harness-Foundry-1.2.0-generic.zip`：通用运行与搭建入口。
- 8份独立能力ZIP：只取所需能力，不包含SDK或本机依赖。
- `SHA256SUMS`：核对实际下载字节。

在新目录解压并保留隐藏的`.agents/`，使用Python 3.11+：

```bash
python3 tools/hffactory.py version --json
python3 tools/hffactory.py --help
```

期望产品版本1.2.0、协议2.9。能力使用见[接入说明](https://github.com/alexYG-arch/Harness_Foundry/blob/v1.2.0/docs/CAPABILITY_ADAPTERS.md)及[功能指南](https://github.com/alexYG-arch/Harness_Foundry/blob/v1.2.0/examples/capability-adapters/FEATURES.md)。工具在目标环境重新绑定，不复制旧`.venv`；源码、固定包和实际部署分别记录。更新不迁移活动库、不清零累计预算、不重放旧命令，也不会自动替换既有Harness。

- 新DOC输入完成生产CLI及事先声明的独立验收CLI调用；完整正文、顺序及引用一致。目标看板完成内嵌、Chrome全屏、真实画中画、历史、重连和前后台核对，页面100%仅指其声明检查范围。
- Qt实际configure/build/CTest/运行及Python依赖观察、Decimal/SQLite计算完成；Python首轮漏列读取根失败保留，经批准沿原第2轮通过。
- 两次原报告取回不重放业务、不重复扣额；成功检查临时区、本轮服务和测试窗口已清理，归档报告仍可核对。

未改变的DATA、text-count、项目运行及旧版兼容断言按原版本、环境和输入复用，不声称本轮重新执行全部能力。原产品实现提交f72222f的完整回归为2572项：**2515 PASS＋57 SKIP**，零失败／错误；其90项受影响验证及不同平台源码检查有重叠，不相加。

正式版另核对版本相关源码检查、固定包与选定提交、包内加载与入口、main和标签CI及发布后下载。rc.3真实业务证据只在实现与依赖未变的范围适用，不改写为1.2.0新模型运行；最终附件身份及发布阶段结果见本Release。
