# Harness Foundry v1.3.1

版本 **1.3.1**，协议保持 **2.9**。这是v1.3.0之后的沙箱启动及接收器接续修复，基于 `2abecf0` 和CI断言补正 `7caece6`。保留旧标签、Release、附件、失败证据及累计预算，不增加控制器或逐次确认。

## 本次修复

- Codex接收器同时绑定声明入口、实际入口、解析目标及文件身份。普通二进制使用实际路径；脚本包装器保留原argv入口，不全局改写普通工具或Python虚拟环境路径。
- 准备与正式派发复用状态目录、公开材料与配置检查。受限启动探测与帮助、配置读取和模型调用共用原命令时限；诊断复用不替代当前身份、批准或操作系统权限核对。
- 明确的同步准备拒绝保存为启动前失败；父进程启动后的helper失败保留阶段诊断。缺失退出观察仍为未知，不伪造捕获、退款或自动重试资格。
- 同范围检查器纠正比较已绑定的接收器身份，拒绝静默换绑或丢失绑定；旧prepared保持历史兼容。沿Readback返回的scope接续时保留原声明并重新核验。
- 明确改选入口使用现有 `prepare-build-authorization` 的 `rebind_from` 和可选顶层 `replace_codex_receiver: true`。必须取得对应真实批准，不能自动继承旧批准；未改选的后续同范围修正仍可依法接续。接受复用、只复验、累计消耗及完整报告取回保持原机制。
- CI测试显式使用二进制别名，同时检查原声明与实际入口；保留完整scope比较、不派发进程及不创建目标断言。

具体使用见[固定版本CLI](https://github.com/alexYG-arch/Harness_Foundry/blob/v1.3.1/docs/GENERIC_BUILD_CLI.md)、[运行说明](https://github.com/alexYG-arch/Harness_Foundry/blob/v1.3.1/docs/GENERIC_BUILD_RUNTIME.md)及[实施记录](https://github.com/alexYG-arch/Harness_Foundry/blob/v1.3.1/docs/FOUNDRY_CODEX_SANDBOX_STARTUP_IMPLEMENTATION_2026_11_11_V1.md)。这些说明不构成新的运行授权。

## 下载与升级

从[本版Release](https://github.com/alexYG-arch/Harness_Foundry/releases/tag/v1.3.1)获取 `Harness-Foundry-1.3.1-generic.zip`、所需独立能力ZIP及 `SHA256SUMS`。运行ZIP由本版明确提交构建，GitHub自动生成的源码ZIP不是运行交付包。

8个能力包版本与字节保持不变：qt-cmake@3、python-environment@2、data-summary@2、doc-export@2、host-review@2、local-dashboard@5、text-count@2、reference-notes@2。复用旧发布附件前核对摘要与本版源码，不重新打包未变能力，不包含具体第三方提供方实现。

在新目录完整解压并保留隐藏的 `.agents/`，使用已声明的Python 3.11+执行：

```bash
python3 -I -S -B tools/hffactory.py version --json
```

预期产品版本1.3.1、协议2.9。已有进程安全交回后再切换实际入口；保留原控制库、产物和报告，不复制不可迁移的.venv，不替换运行中的固定材料。默认接续保留旧声明；需要更换入口时明确提出改选并沿原真实批准入口继续，不能靠删别名或改PATH绕过身份检查。发布不自动升级旧部署、不续期、不增额、不迁移活动库，也不因取回报告再次执行原命令。
