# Harness Foundry v0.3.0

产品版本 **0.3.0**，协议版本 **2.9**，MIT 许可。唯一发布仓库为
[alexYG-arch/Harness_Foundry](https://github.com/alexYG-arch/Harness_Foundry)。

本版汇集 v0.2.0 之后的通用搭建质量、验收契约、运行上下文及接口修复。
**按用户明确批准的限定证据范围发布；新版固定 ZIP 未重跑同包双案例，不宣称完整发行验收。**
不追加真实模型评测，不运行动态攻防或可选安全加固。

## 下载与开始使用

在 [v0.3.0 Release](https://github.com/alexYG-arch/Harness_Foundry/releases/tag/v0.3.0)
的 Assets 下载 **Harness-Foundry-0.3.0-generic.zip** 和 **SHA256SUMS**。
ZIP 由 tag 对应的明确 Git 提交组装，不读取未提交工作区；Release 附件中的
SHA256SUMS 给出该 ZIP 的下载完整性校验，不是认证或业务验收结果。
不要把 GitHub 自动生成的 Source code ZIP/TAR 当成通用运行包。

解压到独立目录，保留隐藏的 `.agents/`，在 Codex 中打开，然后只读检查：

```bash
python3 tools/hffactory.py version --json
python3 tools/hffactory.py --help
```

版本输出应为 `implementation_version: 0.3.0`、协议 `2.9`、
`product_route: GENERIC_REVIEWED_BUILD`。这些检查不会调用模型或创建业务工程。
后续使用仍先审阅搭建文档，再批准具体运行范围；范围内自动实施、独立检查、修复和继续，
不增加逐任务人工批准。详见[在线使用指南](https://github.com/alexYG-arch/Harness_Foundry/blob/v0.3.0/docs/USER_GUIDE.md)。

## 相比 v0.2.0 的主要变化

- 加强需求推导、能力复用、接口衔接及最小范围修复的搭建指引。
- Plan 1.1 提供验收前置关系、只读环境预检和文件效果约定；保留 Plan 1.0 兼容。
- 给任务提供当前已接受的正式输入、相关失败历史和下游义务上下文；恢复复用已完成命令观测。
- 统一结构化合同缺口与失败分类，区分业务失败、检查器错误、跳过和零用例，不再混作返修成功。
- Task/CSV 准备模板只展开当前案例，减少多案例共用文字造成的范围误读。

沿用同一通用控制器、进度存储和授权范围，没有新增引擎或状态库，也没有恢复旧
Start Package/Candidate/epoch/A3 新建流程。本次版本发布不再修改运行算法。

## 验证依据与限制

本次发布只使用既有公开源码门禁、固定提交打包检查和下载后的 version/help 加载检查；
相同发布提交的 GitHub CI 必须完成且通过后才发布，不接受失败或跳过冒充通过。
本地与 CI 的具体结果见 [Tracker](https://github.com/alexYG-arch/Harness_Foundry/blob/v0.3.0/docs/V2_9_IMPLEMENTATION_TRACKER.md)
及 Release 的提交/CI 记录。
本次本地同门禁 **279/279 PASS**，零跳过、失败、错误；首轮文档链接失败及修正记录保留，
不以重跑抹掉失败历史，也未修改测试规则。

既有真实模型评测及失败证据保持不变：Ledger 小样本内中位耗时降低 19.0%，Config 为 1.2%；
原 Task 失败保留，两个后续隔离 Task 样本业务通过。最新样本不是再次提速证明，
也不是跨模型或所有故障的稳定性证明。详见
[评测与交付摘要](https://github.com/alexYG-arch/Harness_Foundry/blob/v0.3.0/docs/FOUNDRY_UPGRADE_EVALUATION_2026_10_10.md)。

既有评测绑定原源码/样本，不能转记为当前固定 ZIP 的新实测。用户明确同意本次
不以未重跑的同包双案例作为发布前置；这只改变本次分发决定，不把 NOT_RUN 变为 PASS。
包内 `acceptance_claimed=false`、工具报告的 `release_accepted=false` 与
`harness_e2e_verified=false` 继续保留。Manifest 的发布状态表示分发状态，不是工程认证。
未接入或验收的目标项目不能据此宣称其历史问题已解决或后续零返修。

## 环境、升级与旧版保留

需要 Python 3.11+；通用运行包只使用标准库，不捆绑模型、凭据或项目工具链。
原生执行需要用户自己的可用 Codex、模型服务与受支持沙箱。
Linux 源码 CI 不等于 Linux/Windows 原生执行验收；其他 CLI/模型版本须先核对接口和权限。
macOS 原生运行不要把包、输入、控制库或目标放在共享 `/tmp` 或 `/private/tmp`。

使用独立目录升级，保留旧程序、输入和状态；不自动迁移旧控制库，不继承旧运行授权。
代码回退不撤销已发生的业务副作用，也不允许静默降级读取不兼容数据。

`Harness-Foundry-0.2.0-generic-3c52c30.zip` 和 SHA256SUMS 均保留不变。
