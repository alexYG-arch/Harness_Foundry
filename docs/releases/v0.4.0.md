# Harness Foundry v0.4.0

产品版本 **0.4.0**，协议版本 **2.9**，MIT 许可。

本版将清晰表达规范、可选中文状态摘要和提示词同步能力带入运行包。
保留默认 JSON 接口、退出码和权限边界，不增加逐任务人工审批。
**本版固定 ZIP 未重跑同包真实模型双案例，不宣称完整发行验收或真实模型表达效果已改善。**

## 下载与开始使用

在 [v0.4.0 Release](https://github.com/alexYG-arch/Harness_Foundry/releases/tag/v0.4.0)
的 Assets 下载 **Harness-Foundry-0.4.0-generic.zip** 和 **SHA256SUMS**。
运行 ZIP 来自 tag 对应的固定 Git 提交，不包含未提交工作区或私有运行数据。
SHA256SUMS 用于核对下载完整性，不代表业务验收。
不要把 GitHub 自动生成的 Source code ZIP/TAR 当成通用运行包。

解压到独立目录，保留隐藏的 `.agents/`，在 Codex 中打开，然后只读检查：

```bash
python3 tools/hffactory.py version --json
python3 tools/hffactory.py --help
```

预期 `implementation_version: 0.4.0`、协议 `2.9`，
`product_route: GENERIC_REVIEWED_BUILD`。这些命令不调用模型或创建业务工程。
实际搭建仍先确认搭建文档，再批准模型、工具、读写范围和预算；批准域内自动实施、
独立检查、修复和继续。详见[使用指南](https://github.com/alexYG-arch/Harness_Foundry/blob/v0.4.0/docs/USER_GUIDE.md)。

## 相比 v0.3.0 的变化

- 对话、文档与发行模板共用清晰表达规范：先说结论和用户影响，再给必要证据；解释术语，
  区分事实、推断和未验证事项，不用内部状态名代替说明。
- 新增 `read-build --human` 中文只读摘要。默认 JSON、`--json`、退出码不变；
  摘要不改状态、不启动任务，也不替代运行范围审阅。
- 正常实施和预算内返修提示内嵌同一规范，并要求写入任务已声明的 Harness 指导产物。
  不额外创建文件、扩大权限或添加审批门禁，不追溯改写已有项目。

沿用现有通用 Build 控制器、授权和进度存储；旧 Candidate/epoch/Driver 新建路线不恢复。
本次发行准备仅同步版本与说明，不修改运行算法。

## 检查依据与限制

发布前使用既有公开源码门禁及相关回归，保持原 20 个测试模块；相同来源提交的
GitHub CI 通过后，才按该固定提交打包并检查 ZIP 完整性与 version/help 加载。
具体提交、CI 链接、检查结果及 ZIP 校验值在 Release 中记录。
源码记录见 [Tracker](https://github.com/alexYG-arch/Harness_Foundry/blob/v0.4.0/docs/V2_9_IMPLEMENTATION_TRACKER.md)。

本次不追加真实模型评测，不运行动态攻防或可选安全加固。既有评测和失败证据保留，
不转记为本版新实测；详见[原评测摘要](https://github.com/alexYG-arch/Harness_Foundry/blob/v0.4.0/docs/FOUNDRY_UPGRADE_EVALUATION_2026_10_10.md)。
提示传播和接口回归证明表达要求被送达且接口兼容，不证明任意模型都会遵守或读者理解效率已提升。

包内 `acceptance_claimed=false`、检查报告的 `release_accepted=false` 与
`harness_e2e_verified=false` 继续保留。发布状态描述软件分发，不把未运行的验收改为通过。

## 环境与升级

需要 Python 3.11+；运行包只依赖标准库。实际执行需要用户自己的可用 Codex、模型服务
与受支持沙箱，不捆绑凭据或目标工具链。Linux 源码 CI 不等于 Linux/Windows 原生执行验收。
macOS 原生运行不要把包、输入、控制库或目标放在共享 `/tmp` 或 `/private/tmp`。

升级使用独立目录，保留旧代码、输入和状态，不自动迁移旧库或继承旧运行授权。
