## 目标和完整输入

验证更新后的同一 Foundry 包能从原始材料推导计划、建设 Codex-carried Coding Harness，
并在新会话实际使用中完成公开小型业务。测试不是第三个产品或专项视频建设。

- 新建：[Task CLI 完整 PRD v0.1](../examples/task-cli/PRD.md)，A1–A6 全部保留。
- 增量：[CSV 项目说明 v0.1](../examples/csv-increment/PROJECT_BRIEF.md)，B1–B5 全部保留；
  同目录 starter 的程序、原测试与 USER_NOTES.md 是完整输入，不覆盖这些来源。
- [修补与双层测试计划 v0.2](FOUNDRY_BUILD_QUALITY_REPAIR_AND_TEST_PLAN_v0_2.md)。
- [独立 Run Test 方法 v0.3](../devtools/release_acceptance/RUN_METHOD_v0.3.md)。

无需新增 UI、账户、网络业务、框架、服务、第三个大型工程或性能 SLA。
Task CLI 仍仅 add/list/complete/delete、JSON 持久化和原错误合同；CSV 仍仅保留 summary、
新增 audit/strict、原格式与用户笔记。测试数据可变化，公开行为不得偷偷增加。

## 能力归属与搭建方案

Codex 承担理解、方案、实现和调试；Foundry 复用已有范围、依赖、独立检查、有限修复与
耐久恢复。生成的项目 Harness 仅实现该项目开发合同、工程指引、检查/使用入口和适配。
确定性业务观察使用本地 Python 标准库，不搭第二运行器或数据库。

不预填旧 H/U/E/F 的 Plan 作为答案。确认后由 Agent 从完整材料推导实际 Requirement/Plan，
语义核对逐项覆盖需求、产物、实际使用与失败返回。内部阶段、命名、算法和目录组织开放，
但观察器与输出之间必须有明确接口，不能仅以模板/帮助信息通过结束。

每例交付可读、可加载的 Harness、必要本地检查入口、实际开发的应用/测试/说明及独立
业务结果。检查器在实施写域外；模型自报、HARNESS_USE.md 或 PLAN_CHECKS_ACCEPTED 均非
完整交付证据。加载入口和检查入口要由真实新会话使用，不只检查文件存在。

## 两项 Task 开发任务与故障安排

1. 首个使用会话依据生成 Harness 完成完整 Task CLI 实现，外部观察器验收原 PRD。
2. 第二个新会话使用**同一版本 Harness**，诊断和修补一个原合同内的 Task 业务缺陷。
   若首次开发没有合适的自然缺陷，在事先声明的一次性副本中使 add 返回错误业务对象；
   该副本先被独立检查拒绝，再由 CODEX 任务实际修改、复验和推进。不能由观察器撤故障。

两项任务及副本的输入/输出依赖提前进入 Plan，第二项在最终完成判定之前执行。
不手改已验收应用、Harness 或控制库；固定 Harness 文件在每项使用前后比较，允许业务
代码和声明运行数据变化。两次不同参数运行不算跨任务复用。若 Harness 必须改变，保留
原复用失败，修改后的版本须获得自己的两项任务证据，仍受剩余范围/预算约束。

CSV 在另一新会话完成既有项目增量，原 API、原测试和笔记保持。两个案例最终必须使用
同一个 Foundry 包；本文不要求两个项目共享同一个项目 Harness。

## 实际验收

| 范围 | 观察与判断 |
|---|---|
| B01 方案质量 | 完整材料→文档→真实推导的 Plan；逐项需求覆盖、能力归属、必要歧义处理 |
| B02 建设和使用 | 两例真实建设、新会话实际使用；首轮失败/未就绪与修复后结果分别报告 |
| B03 接口组合 | 同一公开检查入口在 app 内与外部临时目录运行，绑定解释器传到子进程；保护源文件 |
| B04 留出与关系 | 少量未用于 A 调试的合法/非法实例和路径变化；CSV 行重排保留汇总计数，行级诊断按新顺序重算 |
| B05 真正修复 | 外部断言拒绝→正确生产者有界修改→复验→后继；不得把观察器重试/恢复原副本算模型修复 |
| B06 中断恢复 | 在指定 CODEX 实施完整耐久观测之后、控制提交之前停止宿主；新宿主读状态续跑，不重做、不退款 |
| B08 真实边界 | 合同缺口、错误检查器或失效范围在一次性隔离场景正确暂停；已有充分本地证据不重复调用模型 |
| B09 同版复用 | 上述两项 Task 开发任务在不同会话使用同版 Harness，分别有外部业务结果 |
| B07 最终停止 | 所有约定交付完成后再次 read/advance 零新增实施/模型调用；不自动追加优化 |

正常、错误业务及检查器崩溃对照先检查 Oracle 自身。留出数据依据公开合同，不隐藏新需求；
若其失败被用于修复，就转为回归实例，使用预先保留的少量后备实例，不无限换种子直到绿。
首轮、每次修复、最终版本、未运行场景及原始命令/观察保留。重要新增机制要有实际触发与
作用证据，但不做全库消融或事件 Hash 链。本轮不主张性能收益，不安排旧包或多模型比较。
