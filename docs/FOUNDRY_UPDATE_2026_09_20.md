## 1. 通用建设入口

- 新增领域无关的 Requirement/Plan 编译、完整本地来源读取和来源定位校验。
  不注入视频、指定 Skill 或固定业务阶段；读取完整文件不等于自动完成语义审查。
- 所有 Harness 搭建需求保留澄清问答，先输出版本化搭建文档，用户 Review 并明确确认后
  才能进入 Foundry。共享门禁覆盖通用与旧兼容入口，文档变更使旧确认失效；旧委托、
  后台 PASS 和代理自批不能替代人工 Review。真实消息和语义范围由可信聊天宿主核对。
- 文档确认与运行批准分开。公开 CLI 支持提案、来源捕获、范围准备、批准、撤销、推进、
  未知结果处置和只读状态恢复。范围准备不运行目标；一次真实范围批准覆盖预算内的
  实施、独立检查、修复和后继推进，无逐 Workpack 人工门。
- 新控制流复用 SQLite，采用 `REVISION_V1`、事务和幂等请求，不新增事件/消息 Hash 链；
  仅对指定验证器和产物保留必要字节身份检查。历史数据库不自动迁移或继承批准。

入口及合同：[Build CLI](GENERIC_BUILD_CLI.md)、[Plan](GENERIC_BUILD_PLAN.md)、
[来源](GENERIC_SOURCE_INTAKE.md)、[Runtime](GENERIC_BUILD_RUNTIME.md)。

## 2. 执行、验证与恢复修复

- 原生 Codex/local 接收器持续排空 stdout/stderr；机器协议直接从原始字节增量解析，
  与有界人读摘要分离，避免长输出和跨块中文导致终态丢失。真实超限和落盘失败仍停止。
- 命令计划、观测和验收使用同一控制库；完整宿主附件可用于恢复未提交观测，部分 Case
  只续跑未派发的检查，不重复已完成实施。进程结束不等于业务验收，未知效果不盲目重放。
- 独立验证的基础设施失败与业务断言失败分流：检查器崩溃、依赖缺失或未分类失败停止，
  不驱使模型重写业务；正常业务失败才进入批准预算内的修复。控制器提交验收后才推进后继。
- 声明产物变更按依赖关系失效相关任务，保留无关分支、历史和预算；不以清空历史“恢复”。
- 新增 `executable://NAME` 参数引用，将同一 scope 中原始解释器路径传给二级进程，
  保留 venv/别名身份。未知引用在准备及重规划时拒绝，不猜 PATH、不隐式扩权。
- 补充原生离线预检要求：二级进程、实际依赖、场景写域及零写限制。单测或沙箱
  `true` 探测不能证明真实执行链准备完成；发现依赖缺口后仍需明确运行范围。

此前 17 个待同步提交还覆盖 Candidate 原生启动、耐久命令观测、编码协议、Lab 协议基础、
原生独立检查以及验收证据消费。这些属于兼容链路能力，不能替代通用 Harness 端到端验收。

## 11. 停止维护旧新建流程，统一通用 Build

用户明确确认后，公开脚本、console 和旧模块 main 统一分发到通用 Build。
旧新建、编译、推进、运行授权、交接和打包命令返回 `LEGACY_WORKFLOW_RETIRED`，
不读取请求、不创建状态、不提供兼容回退。包顶层不再导出旧控制核 API。
新项目只走搭建文档 Review、具体运行范围批准及范围内自动实施/验证/修复/恢复。

旧数据库、Candidate、来源快照与批准不改写；新增 `read-history` 直接只读原始
authoring snapshot，不加载旧服务/生成器、不迁移、不恢复授权，不增 Hash。
对非空 WAL 不忽略也不修改，要求先正常关闭旧数据库。通用 revision 库仍用 `read-build`。

AGENTS、Skill、README、CLI 文档及 Manifest 同步为单一新建路线。旧 41 能力诊断
明确标注历史基线，原行为回归通过测试专用入口保留，不冒充新产品公开能力验收。
新增退役无副作用、真实入口防回退、帮助/元数据一致性、历史读取和 WAL 回归。
