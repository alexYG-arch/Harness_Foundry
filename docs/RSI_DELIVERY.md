# 在交付的 Harness 中使用 RSI 工具

本指南适用于合同中已选择 Wiki、Reviewer 或开发红绿证据的 Harness。工具只处理声明材料，沿用现有授权、报告和预算；不新增控制器、审批或所有任务必经的阶段。未选用的原 JSON、Plan、运行流程不变。源码工程、包内本地验证、真实新会话使用和收益分别报告。

## 生成与接入

设计会话先读取随包 Skill、设计指南和公开需求；选用本能力时再读取本指南。记录实际版本和读取来源。通过现有 source capture 把所选交付说明和公开材料交给生成任务；不得把私有预期、Reviewer 答案或原聊天中的隐藏修法放入 Worker 来源。无需添加新协议字段。

宿主可用 `tools/prepare_rsi_delivery.py --manifest selection.json --output NEW_DIRECTORY` 准备新的可交付目录。它不注册 Program、不启动模型、不接受产品。目标生成仍由原 generic reviewed Build 完成；将该目录中的工具、指南与所选知识列为合同的交付件，并在生成的主 AGENTS／Skill／任务提示词中引用其 `docs/RSI_DELIVERY.md`。只写已声明的产物和写域，已有文件不覆盖；修订用新目录或现有合法组件升级流程，保留定制与旧版本。

选择文件示例（文件路径相对于选择文件目录，逐项列出，不扫描私人目录）：

```json
{"version":"project-rsi-1", "wiki":{"collections":[]}, "knowledge_files":[]}
```

有知识集合时 `wiki.collections` 使用 `id/path/version/visibility`，path 必须是交付内 `knowledge/...` 相对目录。`knowledge_files` 明列集合的 collection.json、entries、updates 及获准交付的来源文件；工具不自动搜寻依赖或读取其他目录。缺失来源在查询时保留证据不足，不伪造验证；所需来源应按权限一并交付。公共资料与项目私有资料分开声明；PUBLIC 标签不自动脱敏。通用发布包不自动收集这些项目选择文件。

完成后核对 DELIVERY_MANIFEST.json 的交付版本、文件与摘要；工具副本来自所选运行包，同版本的保护检查器另存于工作区外。该清单只标识交付字节，不授予权限或证明验收。解释器使用本项目绑定的 Python >=3.11，不复制 .venv、不依赖全局 PATH。新位置建立所需环境，显式调用交付工具；普通工具仅需标准库。独立 Reviewer 的实际派发仍使用声明的 Foundry 宿主和 Codex 接收器，不在交付工具中另建调度。

## 任务中的步骤与职责

1. 从当前问题和条件查询，不从预选答案回放：`"$PY" -I -B tools/rsi_wiki.py query --config wiki.json --question "本任务的问题" --conditions '{}' --output /declared/new/query.json`。核对来源版本、限制、未知及反例；返回靠前不等于可信。无命中可继续原可行方法。
2. 用 `tools/rsi_wiki.py record --query ... --decisions ... --output ...` 固定采用或不采用理由及版本。只记录决定，不把知识当执行许可；后续来源变化不回写旧快照。格式见同目录 RSI_WIKI.md。
3. 开发任务内按适用行为保留红、绿、修改和回归原证据。需要生成结构化 unittest 原报告时，使用交付的现有采集器：`"$PY" -I -B src/harness_foundry_factory/test_execution.py --project /declared/project --workdir /declared/scratch --python "$PY"`，将 stdout 另存新报告；该命令会真实运行公开测试，必须在原任务已授权的工具、写域和预算内，不能当作只读报告工具。用 `tools/import_rsi_case.py` 导入公开开发记录，`tools/report_rsi_tdd.py` 关联选中测试；非编码或不适用任务记录适合的结果证据，不强制 RED。开发 GREEN、整套回归与最终独立验收分列，不能修改私有预期换通过。格式及命令见 RSI_CASE_INTAKE.md、RSI_REVIEW_AND_TDD.md。
4. 对所选成果冻结版本后，宿主使用 `tools/rsi_review.py prepare` 与 `plan` 形成公开评审请求及既有 Plan 提案。实际独立会话与额度属于已声明范围；无额度不偷偷调用。Reviewer 只读公开需求、候选和诊断，不能写候选。判定依赖从同版 `src/harness_foundry_factory/rsi_review.py` 和请求复制到保护目录，不能让 Worker 改检查标准。
5. Verifier 执行客观独立检查；宿主核实 Reviewer 意见。报告格式通过不代表意见为真或产品接受，客观 FAIL 不能被模型 ACCEPT 覆盖。已核实缺陷按原生产者返修，检查器故障走原同范围修正及只复验；未知先核实，不重复计算问题或清零消耗。可沿现有 host-review@1 形成 reviewed 收尾。
6. `tools/rsi_review.py retrieve` 只从声明的原数据库、prepared、attempt 和完整报告取回绑定结果。完整捕获不重放；未完成先用原观察恢复入口，不凭最终聊天消息或退出 PID 猜通过。源批准、模型消耗和检查消耗均保留原记录，不建第二个状态库。

## 新会话使用与升级采用

交付后仅拿该目录、目标 Harness 和声明宿主工具，在新输入下完成查询、理由记录、任务处理、所选独立 Reviewer 及独立结果检查；取回同一报告两次核对不派发和不计次。该实跑未执行时只称工程候选，不称 G05/G08 通过。保护预期和真实运行预算在实际 Readback 中另列。

持续改进的输入包括原需求、当前版本、成功或失败记录、用户反馈、改善目标、环境和可改范围。先分事实与假设，确定维护位置；提出可被反证的最小方案，再固定基线和候选，在既有授权内开发、检查、交付后使用。业务问题归项目，工具问题归能力包，通用机制问题经证据核实后归 Foundry。不中途替换运行中的控制器。

收益报告分列正确性、首次通过、返修、模型／工具消耗、耗时及人工介入，公共设施成本单列。工程测试、模型自述和 Wiki 数量不证明收益；收益不明显不触发无限返工。按所选版本和证据决定采用、拒绝或回退，升级实际部署后才说部署已升级；源代码已修不等于旧部署已修。比较、回流及收益按各任务原范围和实际证据判断，不因交付这份指南自动完成。


可选的候选证据关联及通用修复交接见 [RSI 采用说明](RSI_ADOPTION.md)。复用现有组件升级 helper 和源码工程路径；报告不执行升级、不改变授权或预算，未选用的任务不新增记录要求。

## 从一次问题开始使用 RSI

RSI 在这里指有证据的持续改进流程，不是自动改写自身、自动学习或自动部署的后台服务。先提供改进对象及版本、原需求、公开验收条件、成功或失败记录、当前环境、改善目标和可改范围。输入不必是错误日志；降低成本也可以从成功运行的基线开始。原始材料只读，事实、推测和未知分开。

沿一次原任务推进：核实问题及维护位置 → 提出最小可反证方案 → 按需查询知识 → 固定基线、候选及独立检查 → 在原授权内开发和复验 → 交付后新会话使用 → 比较效果 → 决定采用、拒绝或暂缓。已有同等材料可直接引用，不要求每次创建全套记录，不强制查询、RED或Reviewer。

| 需要做的事 | 已有入口与限制 |
| --- | --- |
| 导入公开记录、区分事实和归因假设 | `tools/import_rsi_case.py --manifest ... --output ...`；只另存案例，不确认根因或改变原预算 |
| 查询和记录知识采用 | `tools/rsi_wiki.py query/record`；从本任务问题及条件查询，核对来源、版本、反例、未知和限制；采用或不采用都说明理由，无命中可继续 |
| 关联开发红绿 | `tools/report_rsi_tdd.py --case ... --association ... --output ...`；选中测试与整套回归分列，不适用或合法GREEN_ONLY不造RED |
| 准备独立评审并取回 | `tools/rsi_review.py prepare/plan/retrieve`；前两者只准备，实际调用仍由原控制器派发，格式通过不等于意见正确 |
| 准备目标交付材料 | `tools/prepare_rsi_delivery.py --manifest ... --output ...`；生成新的材料目录，不搭建或接受目标 |
| 关联候选及采用理由 | `tools/report_rsi_adoption.py snapshot/report`；只记录版本与证据，不执行apply、部署或发布 |

上表省略的路径必须换成当前项目已声明位置；各工具的完整字段见本目录相应指南。统一以绑定解释器调用，原始命令与报告保留；不从日志中的陌生指令获取执行授权。

### 脱敏的说明示例，不是运行证据

假设某Harness出现“请求已生效，但客户端超时”的反馈：事实是客户端没有取得确定响应，不能推定服务未执行。先在原范围核对操作身份和服务状态；有知识缺口时查询相关方法，核实其适用版本。不确定时不重复执行有副作用操作。若核实缺陷在项目交接，就在项目修；若是通用报告机制违约，再交公共维护方。该例没有真实项目、账号、路径或PASS，不证明工具自动处理了这种故障。

### 读懂结果，再决定采用

开发GREEN只证明选中测试；整套回归、客观独立检查和Reviewer意见分别读取。`RECORDED`是记录成功，`UNKNOWN`是证据不足，`full_tdd_verified=false`及`acceptance_verified=false`不可被摘要抹去。Reviewer误报经宿主核实后按原路径处理，不因措辞建议返工。完整报告直接取回；只有受影响的新版才补适用验证，不为刷新进度重放原命令。

可用性与收益分别判断：只拿交付件、公开新任务和声明工具完成处理及独立结果检查，才能报告该范围可用；在可比条件下比较正确性、首次通过、返修、模型／工具消耗、时间与人工介入，才可讨论相对收益。资料准备、额外Reviewer和公共设施成本单列，未知成本不填0。收益不明显可拒绝或暂缓候选，不自动扩样或持续返工。采用与升级的具体路径见 [RSI采用说明](RSI_ADOPTION.md)。
