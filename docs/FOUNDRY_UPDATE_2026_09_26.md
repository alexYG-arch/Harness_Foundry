# Foundry 搭建质量更新 · 2026-09-26

本轮是 **v0.2.0 之后的源码更新，未发布新版本**。实现来源提交为 `b48e3fc`，后续说明提交补齐真实运行结果。
产品版本仍为 0.2.0，协议仍为 2.9；既有 tag、Release 和下载 ZIP 不替换。

## 对使用者有什么变化

### 1. 从需求推导方案，而不是套固定流水线

搭建前先分清 Codex、Foundry 和项目 Harness 各自承担什么，优先复用已有模型、工具、
控制和恢复能力。根据实际输入输出与完整交付要求推导任务，不要求固定阶段名、目录或算法。
通用搭建政策与仓库/发行包 Skill 同步更新；这属于设计指引增强，不是增加一套运行控制器。

### 2. 把衔接问题提前发现

规划时推演一次真实上下游调用，核对参数、数据形状、解释器、路径与读写范围。
运行获准后先做一条可工作的完整小路径，再扩展到约定交付；不把文件存在、帮助信息或切片通过当成完整完成。

### 3. 修在正确的位置，完成就停止

项目业务或局部适配问题优先留在项目内修复；可复现的 Foundry 公共保证缺陷才修对应核心实现。
不能通过放宽检查或改变合同关闭缺陷，也不把每个案例的特殊规则写入通用产品。
仍然保留“搭建文档确认＋一次具体运行范围批准”；范围内自主实施、检查、修复和继续，
不逐 Workpack 请求批准，不要求手输 Hash。约定交付完成后停止，不自动追加优化。

### 4. 双层测试和结果记录更完整

- **TDD 修复检查**：明确缺陷先复现，再在责任实现层修复，运行相邻回归。
- **独立 Run Test**：从原始需求和已确认文档出发，用固定包、真实模型、新会话和外部业务检查验证完整使用链路。
- 首轮与最终结果分别保存；未运行项不会从历史 PASS 补齐。同版 Harness 复用核对实际固定文件字节，不只相信版本标签。
- 对比工具只核对可观察条件，不自动生成性能改善结论，不将模型自报或计划绿色当作交付验收。

测试工具接受 Agent 实际推导的 Plan，旧固定流程仅保留为回归夹具。
工具放在 `devtools/release_acceptance/`，不进入通用运行包；普通用户工程不因此被强加双案例、第二任务或性能比较义务。

## 已保留的能力，不冒称本轮新建

范围内自驱/返修、任务依赖、持久进度、独立验证、预算、到期/撤销停止及耐久观测恢复均沿用现有实现。
本轮没有改写运行控制器、新增状态库或事件 Hash 链，没有恢复旧 Start Package/Candidate/epoch 流程。

源码 CI、真实运行和正式发布是不同结论。本次 Git 更新不发布新 ZIP，不将旧 v0.2.0 附件描述为已包含这些改动。

## 接入与兼容性

新用户仍可使用[已发布 v0.2.0](https://github.com/alexYG-arch/Harness_Foundry/releases/tag/v0.2.0)和[使用指南](USER_GUIDE.md)。
