# 对话与文档的清晰表达规范

本规范适用于 Foundry 对人的答复、进度报告、搭建文档和使用说明。它不改变需求、权限、
运行状态或验收规则，不新增审批门禁。它参考 ASD-STE100 的清晰技术表达原则，适配中文；
不是 STE 合规或认证声明，也不把英文单词数限制直接换算为中文字数。

## 先让读者知道发生了什么

用用户的语言，先给结果，再解释影响和下一步。简单问题直接回答，不必套固定长模板。
状态或故障报告优先说明：

- 结果：完成了什么，或者停在哪里。
- 影响：这些证据能证明什么，还有什么未验证。
- 下一步：谁做什么；仅在确实缺少用户决定时提出问题。

不要用“闭环、对齐、打通”等抽象词代替具体对象和动作。不为普通内部检查反复询问
“继续”；已批准范围内的工作沿用现有 TRUE_GATE_ONLY 规则。

## 保持术语和事实一致

一个概念使用同一个名称。专业术语首次出现时解释，之后保持一致，不为了避免重复而换词。
例如：Workpack 是计划中的任务单元；独立检查判断具体要求是否满足；授权说明允许执行的
范围。不要把文档确认、运行授权、任务检查通过和整个项目验收称为同一种“批准”或“完成”。

一句话集中表达一个意思，写明谁做什么；执行前必须知道的条件放在动作之前。
明确区分事实、推断、建议、已完成和未验证。保留真实的不确定性，不把模型自报当作独立验收。
状态报告以现有控制记录和检查证据为依据，不创建第二份“AI 总结状态”。

简化时必须保留否定条件、必须/允许的区别、权限、范围、预算、单位、版本和已知限制。
代码、命令、错误码、路径、标识符、引用原文和机器 JSON 保持原义与精确拼写。
既有结构化输出必须保持其字段和解析格式；如 foundry_blocker 要求纯 JSON，就不加解释前缀
或 Markdown 围栏。reason 是说明，不代替 failure_kind 分类。

## 文档按读者需要分层

先说明用途、适用对象和限制，再说明使用与设计，最后给出字段、命令和证据等技术参考。
短文可以合并层次，不强制新增章节。搭建文档仍须覆盖
[原有最低内容](GENERIC_BUILD_PLAN.md#上游问答与文档交付)，不能用摘要替代完整需求。

路径、长标识符和 Hash 放到需要它们的操作或证据区；不能隐藏授权决定所必需的完整范围。
图表仅用于确实更容易解释的关系，不强制输出网页、视频或新的交付物。
不要静默改写已确认文档或历史证据。先在草案阶段组织清楚；已确认文档的改动仍遵守原有
版本与确认规则，不借文风调整改变合同，也不为遵守本规范追溯重审所有历史材料。

## 写法示例（不是一次实际运行结果）

不清楚：“生产者消费链闭环，证据投影 PASS，等待推进。”

清楚：“输出文件已生成，检查器也能读取。尚未验证实际使用效果。下一步运行已批准的
使用用例；本次不需要新增审批。”

## 如何检查

作者在既有交付检查中确认：读者能否知道做完什么、没验证什么、原因是什么、下一步谁负责？
表达调整是否保留了原有条件和证据？普通措辞建议不阻断任务，不调用额外模型反复评分，
也不新增审批或完成状态。真实权限变化、合同冲突和无依据的成功声明仍按原有规则处理。

AGENTS/Skill 是模型行为约定，不保证每段自由文本都完全遵守。确定性人读输出只约束其
覆盖的状态展示；结构与兼容性回归不证明人的理解速度提升，也不证明真实模型表达已改善。

## 只读状态输出

`read-build --human` 提供中文摘要。默认格式和 `--json` 接口不变，两种显式选项互斥。
摘要列出计划、授权预算、历史尝试、原始失败证据和已有恢复建议，不替代完整范围展示，
不授予权限、不重新检查历史文档、不推进任务。具体调用见 [CLI 说明](GENERIC_BUILD_CLI.md)。

## 生成 Harness 与运行提示词

通用运行提示内嵌本规范的精简投影，不要求目标额外读取 Foundry 文件或扩大只读目录。
正常实施和预算内返修使用同一提示入口；原任务上下文、失败反馈及机器 JSON 保持不变。

当当前任务的声明产物包含 Harness 的 AGENTS、Skill、运行提示词或使用文档时，生成方
将这些表达原则、机器协议优先和权限限制一并写入这些产物，使用自包含说明。不得引用
Foundry 本机路径或未声明的策略文件，也不为文风规范自动新增文件、任务、检查器或模型调用。
普通业务任务不被改成 Harness 建设任务；没有指导文档产物也不构成阻断。

只在已批准写域及当前声明输出内实施；不追溯改写已确认文档、已验收产物或历史证据。
现有真正决策/权限/合同/未决影响边界不变，不新增逐任务批准或文风评分返修循环。
提示与发行回归只证明规则已送达相应入口，不证明模型生成的每份 Harness 都已遵守；
真实项目采用和表达效果仍需各自既有验收，本轮不追加真实模型评测。
