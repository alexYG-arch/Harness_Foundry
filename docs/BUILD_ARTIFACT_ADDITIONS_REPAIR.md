## 线索核对与归属

只读核对 UX evolution 的本地 runtime 接续补丁、41项历史工程检查记录、接续准备和保全记录。
这些材料支持该项目曾成功接续并保留原消耗与既有验收，不是主版本本轮测试，
也不证明该业务全部完成。本轮未操作其控制库、接续业务或替换其运行文件。

主版本原 `validate_rebind` 要求各任务 artifacts 完全相等，确实无法表达在原任务写域内
补充遗漏产物。本轮复用已有准备、实际批准、接受资格、预算投影及报告恢复，不新增控制器。
没有复制项目特定 Plan、上限、路径、业务名或新的台账，也没有原样合入项目补丁。

## 通用实现

- 保留原任务 ID、Job、依赖、旧产物声明及归属；只允许在原生产者写域内补入新产物 ID。
  Plan 编译器继续核对独立检查覆盖、效果清单、路径冲突、输入和后继替换关系。
- 准备与读取展示 `artifact_additions`；实际批准记录同一差异及新旧关联。准备不是授权，
  同范围检查器修正不能授予新增生产权限；到期、撤销、当前提案、未决效果及派发校验保留。
- 新声明自身不增加或返还额度。显式 `budget_extension` 可在同一次现有批准中组合，
  仍分别绑定上限与追加项。幂等准备/批准、跨 prepared 读取、完整捕获取回不重复计费。
- 未受影响且仍适用的验收直接复用；只改检查绑定的任务仍可只复验。与项目补丁不同，
  不永久禁止已接受或待复验生产者追加输出，而是由既有生产签名判断重建及下游失效。
  旧 PASS 不覆盖新输出，旧事件与检查报告不回改；旧物理版本需要按原流程另行归档。
- 后继替换按每次尝试实际绑定的 Plan 判断，不把旧任务的启动套给后来才追加的产物。
  该修正复用原事件视图，预算投影与历史事件不变；不会提前跳过旧输入的字节核对，
  也不把仍存在的旧物理版本误判为已消费而拒绝合法只复验。

使用入口及步骤见 [CLI 说明](GENERIC_BUILD_CLI.md#同-program-追加产物声明)。
不变的普通准备、合法返修及无关任务不增加逐步骤确认；需要的新范围批准沿用现有入口。
