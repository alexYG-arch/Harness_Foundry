# 通用能力接入、交付与验证边界

本说明对应 1.2.1、协议 2.9。1.2.1保留1.2.0的能力实现与版本，另修复核心累计预算增额；不将旧能力验收改称本版真实模型增额验收。源码包含通用第三方连接接口和内置参考能力，不包含具体第三方提供方实现。此前完整工程目录、固定候选、报告和累计预算继续保留，本发行从明确源码范围另行验证和组装。

## 新增能力与入口

1. `examples/capability-adapters/connections.py` 连接目录或 ZIP，绑定来源、版本并发现目录和基础资料；选中 Skill 按原路径加载。连接不等于安装、运行、授权或业务接受。
2. `prepare.py` 复用原准备入口，描述 v2 可用 `integration_mode: ALL` 或 `ON_DEMAND`。需求引用、功能依赖、工具环境与最终交付形态分别记录。旧无新字段配置继续走原路径。详见 [FEATURES](../examples/capability-adapters/FEATURES.md)。
3. 通用 `native.py` 接收调用方提供的 `adapter_path`，准备原工具调用与完整报告取回；[作者入口](../examples/capability-adapters/AUTHORING.md)支持非标准清单转换及有边界的编译/改写准备，未知行为不推定等价。
4. `stack_handoff.py` 和 `delivery.py` 交付所选文件、版本、功能清单和决定记录。接收端重新绑定本机工具，不复制开发机虚拟环境。私有预期和判定依赖留在保护域，真实结果通过 [check_capability_delivery.py](../examples/capability-adapters/check_capability_delivery.py) 及适用功能检查核对。
5. 继续沿原 upgrade.py、G/C/N、merge/apply 保留定制、已知冲突和旧版本。报告只读归并，不重新派发或计数。所选 RSI 继续使用现有工具与外层交回点，不创建第二个修复控制器。

内置新版本为 qt-cmake@3、python-environment@2、data-summary@2、doc-export@2、host-review@2、local-dashboard@5、text-count@2、reference-notes@2。旧版本保留。各版本从本标签源码或独立能力附件选择，通用 ZIP 不包含第三方 SDK。

## 本次修复

- 按最终交付形态核对依赖，拒绝运行功能依赖未交付的搭建期功能；合法搭建期依赖和正常 AS_IS/BRIDGED 组合保留。
- 采用功能映射的连接只使用新范围的 Skill，保留其他连接与旧无映射入口；搭建期 Skill 可用于实施，但不因此交付到运行端。
- 已有真实未决请求绑定相关来源字节并在交付前复查。相关输入变化重新核对；未选专属文件变化和同字节迁移复用原决定。无真实未决条件不新增确认，旧记录不被回改。

## 验证口径

历史完整开发快照的单轮工程结果为 2518 PASS＋57 SKIP，另有重叠的源码、Skill 和包内验证。这不是本发行的测试数量：发行范围排除了未纳入的提供方代码及其6项专用测试，但保留全部通用断言；原完整快照及6项证据继续留在原工程目录。所选发行源码的具体结果另见[发布说明](releases/v1.2.0.md)，不把不同集合相加。

原计划WP01–WP08工程与本次标准内置、本机样例范围的出口均为8/8；分母未变。真实执行绑定rc.3固定包，1.2.0保留相同运行实现与能力字节，仅更新身份及说明，依最终逐文件差异复用适用证据，不把旧报告改绑为新执行。

## 升级采用

在新目录解压固定包并核对 SHA256SUMS、版本和实际加载位置；项目工具按目标环境重新绑定。先按项目需要准备选择和交付，再沿原合同、授权、独立检查和报告恢复流程使用。来源换版不自动改旧批准或清零预算；源码已合入、发布附件已提供、目标部署已升级分别记录。正式发布不表示既有目标已自动升级，也不扩大已验证的平台与业务范围。
