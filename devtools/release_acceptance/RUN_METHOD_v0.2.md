# 双案例有限验收方法 v0.2（未授权运行）

本文件更新运行/测试接口，不修改已确认的 Task CLI 和 CSV 增量业务范围。
它不是搭建文档确认或运行批准；旧预算、检查器绑定、失败和包均不沿用。
本目录为发布开发工具，不进入通用发行包、不设为用户工程的默认阶段。

## 接口与责任

- H 生成的 `check.py --project APP --workdir SCRATCH --python BOUND_PYTHON`
  支持 `--help`；参数接受调用方明确提供的现有目录和解释器，不写死本机路径。
- SCRATCH 可以是 APP 内专用子目录（开发调用），也可以位于 APP 外（只读验收）。
  只能在当前批准域内写临时数据；源码快照只排除指定子树，不排除整个 APP。
- 所有测试和嵌套子进程消费 `FOUNDRY_TEST_WORKDIR`、`BOUND_PYTHON` 和临时目录环境。
  U 自己执行时在 app 内准备数据；不能据此把 app 路径硬编码进可复用测试。
- 检查器 stdout 为一个 JSON：通过为 `CHECKS_PASS` / exit 0；失败为
  `CHECKS_FAILED` / exit 1，附 `failure_kind`、原因及嵌套 evidence。
  已公开业务断言用 ASSERTION；准备/发现/进程异常保留阶段、类型和原结果，使用
  INFRASTRUCTURE；合同缺口用 CONTRACT_GAP。不得把子进程任何非零退出都包装为 ASSERTION。
  正常预期异常不属于运行失败。日志写 stderr，不污染 JSON。
- 可使用选定包中的 `test_execution.py` 运行 unittest；路径由宿主显式绑定给观察器。
  这不是沙箱，也不能代替外部独立业务断言。非空正常和错误业务对照必须仍然存在。

## 组合检查与交付界限

H 的资源检查增加实际 `--help` 调用，确认公开入口可调用。U 要在自己的合法写域真实
调用该入口并记录使用。H/U 的阶段检查只用于有界建设推进，不是完整 Harness 交付。
E 的可信 LOCAL 观察器在同一批观测中运行两种布局：

1. 把 app 复制到本次 scenario 临时域，按 U 的 app 内 workdir 调用同一入口和测试；
   只改一次性副本，仍保护副本中 workdir 之外的源码。
2. 读取真实已验收 app，数据写外部 scenario；原生沙箱禁止 app 写入。
3. 独立 verifier 检查两组结构化结果和原有完整业务观察，再允许后继。
4. 在另一个一次性副本中仅使 Task add / CSV audit CLI 返回错误业务结果，保留模块
   导入接口。生成的 Harness 必须以 ASSERTION 拒绝；始终 PASS 的检查器返回 H 修复，
   崩溃/基础设施错误不能充当有效负例拒绝。真实 app 不改。

只有两种布局、业务行为、实际新会话使用与恢复证据组合完成，才讨论案例交付。
H/U 的 AST/帮助信息通过不能代替这一关。源码预检先用离线夹具覆盖同一组合；实际
生成入口是否遵守全部约定仍待新的有界真实运行，不由 Prompt 或环境变量自动证明。

## 修复归属

Task 第一次 E 的 no-op add 为已展示的合成缺陷，只改一次性副本；仍应被独立业务
判定拒绝，随后原 E 在原预算内观察真实 app。非合成业务错误由 verifier 指向 U-0。
生成测试的明确断言可指向 U 的产物；已确认检查入口 JSON/退出约定违约指向 H-2。
这些 ID 对应本目录 `prepare.proposal`，不是由目标进程自行选择权限。
无法判断责任的嵌套异常停止诊断；不根据 PermissionError 字样推断平台坏了或自动重写业务。
Foundry 按已批准计划核对输入生产者，失效受影响的验收并在原预算/写域内修复。

## 恢复探针

`recovery_probe.after_observation_runner` 包装已有、已批准的 NativeBuildRunner：
只在指定 H 的 CODEX 实施返回 `MODEL_TURN_COMPLETED` 且 exit 0 后退出 86。
Native 已先持久化结果，控制器尚未记录该次观察/接受，也未释放 U。
任何普通失败、LOCAL PASS 或 advance 正常返回都不能算中断窗口。
`advance_with_probe` 未实际中断时返回非零 6，并保留真实推进结果。

之后由新的宿主使用原控制库 `read-build` / `advance-build`：先检查当前授权与原余量，
从耐久观察恢复，不重复 H 实施、不退次数；独立检查后才进入后继。
本地回归的合成模型形状不是实际模型中断证明。

## 再运行准备

`prepare.proposal` 是无状态函数，调用方必须提供包、来源、路径、模型、工具、预算和期限；
它不创建 Program/目标、不写批准或调用模型。固定新版附件后，宿主展示两例共同包身份与
新检查器/运行差异，再获取一次有限范围批准；无需重复确认未改变的业务文档或逐任务批准。
旧报告/数据库不编辑、不复制其通过状态到新范围。本轮源码修复不是正式发布许可。
